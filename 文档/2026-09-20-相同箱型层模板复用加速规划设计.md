# 相同箱型层模板复用加速规划设计

## 概述

当前 `StackPlanner.GeneratePlan()` 使用有限宽度搜索规划 `OnShelf` 箱子。箱子数量较多时，同一箱型的每个箱子都会重复生成候选点、复制占用集合并扩展搜索分支，规划时间和内存分配明显增加。

本方案利用“相同长度、宽度、高度的箱子在相同层面具有相同几何放置规则”这一事实：先为某一箱型规划出一层布局，将该层的 X/Y/朝向保存为内部模板；后续同箱型箱子优先直接套用模板槽位，仅做低成本的支撑、碰撞和边界验证。模板不能套用时，自动回退到现有有限宽度搜索，保证正确性优先于加速。

## 相关文件

- `StackPlanner.Core/StackPlanner.cs`：增加模板缓存、模板生成、模板套用和回退逻辑。
- `StackPlanner.Core/Contracts.cs`：不修改公开契约和输出字段。
- `StackPlanner.Core/文档/2026-09-20-最大箱数紧凑堆垛规划设计.md`：现有有限宽度搜索和确定性约束的来源。

## 目标与非目标

### 目标

1. 相同箱型数量较多时，减少重复候选生成和搜索分支扩展。
2. 不使用并行任务，不主动提高 CPU 峰值。
3. 保持规划结果确定性：相同输入必须得到相同坐标、朝向、层级和顺序。
4. 保留边界、间隙、碰撞、稳定支撑和最大高度检查。
5. 模板不适用时保持现有搜索结果能力，不因优化导致错误放置。
6. 不修改 `BoxPlacement`、`StackPlanResult` 和 `Box` 的公开字段。

### 非目标

1. 不把不同尺寸但外观相似的箱子合并处理。
2. 不跨越已成功固定箱子的真实位置强行复制模板。
3. 不追求数学意义上的全局最优，也不引入复杂的精确装箱求解器。
4. 不缓存跨次 `GeneratePlan()` 的几何结果；箱子状态、固定占用或箱子集合变化后，跨次缓存容易失效，第一版只在一次规划调用内部复用。

## 方案选择

采用“**层模板复用为快路径，现有搜索为安全回退**”的混合方案。

选择原因：

- 仅减少 `BeamWidth` 会改变搜索质量，不能从根本上消除相同箱子的重复计算。
- 直接把所有相同箱子折叠成数量会破坏箱号、Order、成功状态和输出逐箱对应关系。
- 层模板只复用几何槽位，不合并业务箱子，既能批量加速，又能保留当前公开行为。
- 通过一次次几何验证处理不同支撑面和固定占用，模板失效时回退，风险比强制复制低。

## 核心逻辑

### 1. 箱型签名

在 `StackPlanner` 内部使用现有 `BoxTypeKey(Box)` 作为模板键。长度和宽度按无方向尺寸归一化，高度参与签名；箱号、重量和输入枚举顺序不参与箱型判定。

同一次 `GeneratePlan()` 内，为每个箱型维护一个内部模板缓存。缓存仅包含几何布局信息，不保存具体箱号，因此可以绑定到该箱型的任意剩余箱子。

### 2. 模板内容

模板由同一层内的若干槽位组成，每个槽位记录：

- 相对于模板锚点的 X/Y 偏移；
- 0° 或 90° 朝向；
- 槽位在该层的确定顺序；
- 生成模板时的层内几何包围范围。

模板不保存公开 `Order`、箱号和绝对 Z。套用时由当前箱子生成新的 `BoxPlacement`，并根据当前支撑面重新计算 Z 和层号。

模板锚点采用该层第一个槽位的中心点，所有偏移统一保留固定精度。这样可以避免直接复制旧箱号和浮点累计误差。

### 3. 模板生成

在 `SearchOnShelf()` 的搜索状态中，当某个箱型第一次被选中并成功放置后，继续沿用该箱型生成当前最低层的槽位，直到满足以下任一条件：

1. 当前层不能再放置该箱型；
2. 当前层已达到该箱型本次可复用的槽位上限；
3. 下一个槽位需要切换到更高层；
4. 当前状态包含固定占用或支撑结构，使模板继续扩展可能不安全。

成功生成的同层槽位归一化为模板并放入本次规划的缓存。模板只从已经通过完整几何校验的位置生成，不单独发明新的碰撞规则。

### 4. 模板套用

后续选择到同一箱型时，先尝试模板快路径：

1. 从剩余箱子中按固定 `Order`、箱号顺序取箱子，避免依赖集合遍历顺序。
2. 将模板槽位依次绑定到具体箱号。
3. 根据当前层锚点计算每个槽位的绝对 X/Y。
4. 从当前占用计算可用支撑高度，并生成对应 Z 和层号。
5. 使用现有 `InsidePallet()`、`Collides()`、`Supporting()`、`HasStableSupport()` 和 `Fits()` 逐槽位校验。
6. 所有槽位均合法时，一次性加入占用和布局结果；只要任意槽位失败，丢弃本次套用，不写入部分结果。

模板套用只减少候选搜索，不跳过安全检查。模板必须在同一箱型、同一层级策略和兼容支撑条件下使用；不同层或支撑面不兼容时，重新计算层高，必要时直接回退。

### 5. 模板失效回退

模板不是硬约束。出现以下情况时，放弃快路径，回到原有 `GenerateCandidates()` 和 `SearchOnShelf()` 分支：

- 模板槽位超出托盘边界；
- 与成功箱或非 `OnShelf` 箱子的固定占用碰撞；
- 支撑面积不足或重心不稳定；
- 当前槽位所需高度超过最大堆垛高度；
- 模板套用后会减少当前可规划箱数；
- 风车箱组、已固定箱或其他特殊布局不满足模板前提。

回退结果参与原有 beam 排序，不能因为模板失败而提前判定规划失败。

### 6. 搜索状态和 CPU 控制

模板复用优先用于同一搜索状态内的连续同箱型箱子，避免跨状态复制大量布局。每个状态最多执行一次模板批量尝试，失败后本状态只走一次普通候选扩展。

第一版保留现有 `BeamWidth = 64` 和 `MaxCandidatesPerBox = 32`，不通过增大搜索宽度换取效果。模板缓存使用 `Dictionary<string, LayerTemplate>`，每个箱型只保留一个确定性模板，避免缓存无限增长。

不使用 `Parallel.For` 或任务并发。这样可以降低线程调度、集合竞争和 CPU 峰值，也能保持规划结果与线程数量无关。

### 7. 风车布局和固定占用

现有 `TryBuildWindmillGroups()` 继续作为特殊布局优先路径，不纳入普通模板复用。风车组必须四箱一组、同层完成，避免普通模板拆散风车结构。

`StackingSucceeded` 箱子和非 `OnShelf` 箱子的已有规划占用继续先恢复，模板只能在这些占用之外生成和套用，不能改变其位置。

### 8. 输出和状态一致性

模板套用生成的每个槽位仍对应一个独立 `BoxPlacement`。最终继续经过 `NormalizeOnShelfOrders()`，更新 `Box.Order`、`_lastPlacements` 和 `_lastPlan` 的方式不变。

如果模板只成功套用部分箱子，应仅把完整验证成功的批次提交；批次失败时不保留部分占用，防止状态污染。最终 `PlanningResult` 仍只表示所有箱子是否都获得合法位置。

## 关键方法

- `StackPlanner.GeneratePlan()`：每次规划开始时创建本次调用的模板缓存，并将其传入货架箱搜索。
- `StackPlanner.SearchOnShelf()`：在扩展同箱型分支时优先尝试模板批量套用，失败后使用现有候选搜索。
- `StackPlanner.GenerateCandidates()`：继续作为模板生成和回退路径共用的唯一合法候选来源。
- `StackPlanner.BoxTypeKey()`：提供模板缓存键，保证同尺寸同高度箱子才共享模板。
- `StackPlanner.TryApplyLayerTemplate()`：验证并一次性绑定模板槽位，失败时不修改搜索状态。
- `StackPlanner.BuildLayerTemplate()`：将已验证的同层放置结果转换为相对坐标模板。
- `StackPlanner.TryBuildWindmillGroups()`：保留风车箱组特殊布局，不使用普通层模板。
- `StackPlanner.NormalizeOnShelfOrders()`：继续负责最终顺序和支撑先后关系。

## 性能预期

当同一箱型数量较多且每层布局稳定时，原流程中“每个箱子 × 每个搜索状态 × 多个候选点”的计算会变为“每个箱型首次生成模板 + 后续槽位低成本验证”。预期主要减少：

- `GenerateCandidates()` 的重复调用次数；
- `CandidateHeights()`、`Supporting()` 和碰撞判断的重复组合；
- `SearchState`、`Dictionary` 和 `PlacedBox` 的重复分支复制。

该方案不会承诺固定倍数加速。若箱型混合度高、固定占用复杂或模板频繁失效，性能会接近现有算法，但不应比回退路径更差。

## 测试与验收

1. 相同箱型数量较多时，规划结果逐字段稳定，且规划箱数不低于改造前。
2. 同箱型可连续铺满一层时，后续相同箱子使用同一层模板的 X/Y/朝向规律。
3. 不同支撑面导致模板不适用时，能够回退并得到合法方案。
4. 固定成功箱的位置、朝向、层级和顺序不变化。
5. 风车箱组仍按四箱一组规划，不被普通模板拆分。
6. 输入顺序变化、重复调用和不同箱号下，结果符合既有确定性要求。
7. 增加 100、300、500 个相同箱型的性能测试，记录规划耗时、GC 分配和峰值工作集；测试不得通过并行化制造 CPU 峰值。
8. 所有几何合法性、状态更新、删除、清空和部分规划回归测试继续通过。

## 取舍与实施边界

第一版只做“同一规划调用内、同箱型、同一层布局”的模板复用，不做跨次持久化模板，不做跨不同支撑拓扑的强行复用。这样能以较小改动获得主要收益，并把模板失效风险限制在一次搜索状态内部。

实现前建议保留一次旧算法与新算法的基准对比：如果模板命中率低，优先优化模板命中条件和批量提交粒度，而不是扩大 beam 宽度。用户确认后再进入代码实现。

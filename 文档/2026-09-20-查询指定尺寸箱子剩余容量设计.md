# 查询指定尺寸箱子剩余容量设计

## 概述

为 `StackPlanner.Core` 增加容量查询接口：在当前规划器状态和最近一次规划结果基础上，按调用方指定的箱子长度、宽度和高度，计算当前最多还能完整放置多少个同尺寸箱子。查询过程不能改变现有箱子集合、业务状态、成功箱固定位置或最近一次规划结果。

MuJoCo 测试界面增加尺寸输入和查询按钮，调用 Core 桥接程序返回的容量结果，用于现场快速判断当前托盘还能容纳多少个指定尺寸箱子。界面可以从共享配置中的箱子类别带入尺寸，也允许直接修改尺寸。

## 相关文件

- `StackPlanner.Core/StackPlanner.cs`：增加非破坏性的剩余容量查询接口和查询规划副本逻辑。
- `StackPlanner.Core/Contracts.cs`：增加容量查询结果模型，明确返回数量、可放置性和查询箱子尺寸。
- `StackPlanner.Core/文档/2026-09-20-查询指定尺寸箱子剩余容量设计.md`：记录接口和跨程序调用设计。
- `Mujuco/tests/StackPlannerTests/Program.cs`：增加容量查询命令，将 MuJoCo 当前箱子状态传入 Core 并输出 JSON。
- `Mujuco/stack_sim/view_stackplanner_process.py`：增加查询箱子尺寸输入、查询按钮、异步调用和结果展示。

## 核心逻辑

### Core 查询规则

1. 调用方传入查询箱子的长度、宽度和高度。三项尺寸必须大于零；无效输入直接抛出参数异常。
2. Core 先基于当前箱子集合和当前状态生成最新完整规划，确保查询使用当前真实成功箱、非货架箱和货架箱的最新占用关系，而不是依赖调用方自行拼接位置。
3. 查询使用规划器副本执行，不向原规划器增加临时箱子，不修改原规划器的箱号、顺序、状态、固定占用和 `CurrentPlan`。
4. 副本中先恢复当前箱子的业务状态和规划位置，再按确定性顺序增加临时查询箱。临时箱使用内部唯一编号，状态为 `OnShelf`，不出现在原规划器和对外业务箱列表中。
5. Core 根据托盘面积和最大堆垛高度计算一个不会低估容量的查询上界，然后在当前完整规划的占用集合上逐个生成指定尺寸箱子的合法候选位置并更新临时占用；无法生成下一个合法位置时停止，返回已经完整放置的数量。查询上界保证不会因循环过早结束而遗漏容量，规划器本身仍负责实际边界、间隙和支撑判断。
6. 查询结果中的“最多还能放置”指在当前规划规则、边界、间隙、碰撞、稳定支撑和最大高度约束下，Core 能够连续确认完整规划的最大新增数量。查询不承诺数学意义上的全局最优组合，也不改变正式规划结果。
7. 如果当前已有规划失败或现有箱子无法完整恢复，查询仍返回零个新增容量，并明确当前基础规划不可用；不能把现有未规划箱子当作可忽略的空间。
8. 当查询箱子尺寸超出托盘单箱几何包络时，直接返回零容量和不可放置原因，避免进行无意义的重复规划。

### 公开结果

容量查询结果至少包含：查询箱长度、宽度和高度，当前基础规划是否完整，最多可新增数量，以及查询是否成功。结果模型不返回临时箱的内部编号，避免临时数据污染业务层。

### MuJoCo 调用流程

1. Python 界面读取当前箱子列表、业务状态和已有规划点，沿用现有规划输入格式传递给 C# 桥接程序。
2. C# 桥接程序新增容量查询命令，解析当前箱子 JSON 和查询尺寸，先用同一套 Core 规划输入恢复当前状态，再调用容量查询接口。
3. 桥接程序只输出 JSON 结果，Python 不复制 Core 的几何判断，不根据箱子数量自行估算容量。
4. Python 在后台线程执行查询，避免大数量规划阻塞 Tkinter 主线程；查询完成后在状态区域显示“当前状态下最多还能放置 N 个”，同时记录查询输入、基础规划状态和返回数量日志。
5. 查询尺寸由界面提供：MuJoCo 只显示箱子类型下拉框，不要求用户输入具体尺寸；选择类型后，从共享配置读取该类型的长度、宽度和高度并传给 Core。查询不自动把这些箱子加入当前箱子列表。
6. 当前箱子集合或状态发生变化后，容量结果标记为过期；再次查询前必须使用最新状态，避免用户误读旧容量。

## 关键方法

- `StackPlanner.GetMaxAdditionalBoxCount()`：根据指定尺寸查询当前状态下最多可新增的同尺寸箱子数量，保持原规划器状态不变。
- `StackPlanner.CreatePlanningCopy()`：复制箱子、业务状态和已有规划位置，供容量查询使用。
- `RemainingCapacityResult`：承载查询尺寸、基础规划状态、最大新增数量和可用性说明。
- `Program.ExportRemainingCapacity()`：接收 MuJoCo 的当前箱子和查询尺寸，调用 Core 并序列化结果。
- `load_remaining_capacity()`：Python 侧调用桥接程序并解析容量结果，不执行几何计算。
- `StackTestWindow.query_remaining_capacity()`：根据选中的箱子类型读取尺寸、启动异步查询并更新界面结果。

## 验证标准

1. 空托盘查询标准箱时返回大于零的容量，且重复查询结果一致。
2. 已有成功箱或其他固定状态箱时，查询结果不会改变这些箱子的坐标、状态和规划顺序。
3. 查询完成后，原规划器的箱子集合数量与 `CurrentPlan` 与查询前一致。
4. 查询结果为零时能区分“尺寸不合法/超出包络”和“当前空间不足/基础规划失败”。
5. MuJoCo 修改箱子集合或状态后，旧容量不会继续作为最新结果显示。
6. Python 界面输入不同长度、宽度、高度后，返回结果由 Core 重新计算，不能沿用类别默认尺寸。

# 当前真实箱子的最佳利用率堆垛规划

## 目的

在保留 `PlanBestUtilization()`“按尺寸规划数量并返回利用率摘要”职责的同时，增加一个面向当前真实箱子集合的独立规划入口。该入口直接返回与 `GeneratePlan()` 相同的 `StackPlanResult`，包括真实箱号、堆垛顺序、X/Y/Z、朝向和层号。

本功能不扩展 `UtilizationPlanResult`，不生成虚拟箱号，不重新计算或添加箱子，也不调用正式的 `GeneratePlan()`。

## 调用流程

1. 测试界面通过现有“获取最佳策略”流程调用 `PlanBestUtilization()`，按 `PlannedCounts` 自动创建当前箱子集合；用户也可以直接通过增加、删除箱子维护集合。
2. 用户点击新增的“利用率规划”按钮。
3. 测试程序把当前箱子 JSON 映射为真实 `Box`，调用 `StackPlanner.GenerateBestUtilizationPlan()`。
4. Core 对当前有限箱子集合执行同高度分层、最多三种箱型组合和二维有限宽度搜索。
5. Core 将二维布局槽位绑定到真实箱号，计算三维层高和机械 Z 坐标，返回 `StackPlanResult`。
6. 测试界面把返回结果写入规划缓存和表格显示；原有“规划”按钮仍独立调用正式 `GeneratePlan()`。

## Core 规划逻辑

`StackPlanner.GenerateBestUtilizationPlan()` 先按当前箱子加入顺序分配 `Order`，然后只接受当前处于 `OnShelf` 状态的集合。每个真实箱子最多使用一次；如果集合中存在其他状态，接口返回失败结果，不改变正式堆垛状态。

算法按箱子高度分组，并从同一高度的实际箱型中枚举最多三种类型的组合。`FindBestFiniteDirectLayer()` 在托盘二维区域内使用 0°/90° 候选、20 mm 箱间隙、托盘边界、有限宽度搜索和确定性签名，搜索当前库存能够形成的单层布局。每个搜索状态保存剩余真实箱子，因此不会把箱型当作无限供应。

完成一层后，算法从剩余箱子中继续选择利用率最高的合法同高布局，直到没有可放置箱子或达到 `StackMaxHeightMm`。每层按实际箱高累计底部高度，使用 `PlaceFloorZMm - BaseZ - HeightMm` 计算输出 Z 坐标。

## 输出与确定性

输出直接复用 `StackPlanResult` 和 `BoxPlacement`，不增加字段：

- `BoxNumber` 保留当前真实箱号；
- `Order` 按最终从底层到上层、同层 X/Y 空间顺序重新编号；
- `Xmm`、`Ymm` 为二维布局中心坐标；
- `Zmm` 为机械坐标系中的放置高度；
- `OrientationDeg` 只允许 0° 或 90°；
- `LayerIndex` 为从底层开始的层号；
- 只有全部当前箱子均已放置时 `PlanningResult` 才为 true。

候选遍历、箱型键、箱号绑定和结果排序均使用固定规则，避免受输入枚举顺序、哈希遍历顺序或随机数影响。相同的箱子集合、尺寸、顺序和托盘约束应产生逐字段一致的结果。

## 相关入口

- `StackPlanner.PlanBestUtilization()`：按尺寸和最小数量输出利用率摘要，继续服务“获取最佳策略”自动加箱流程。
- `StackPlanner.GenerateBestUtilizationPlan()`：按当前真实箱子数量直接输出逐箱堆垛结果。
- `Program.ExportBestUtilizationPlanFromJson()`：测试 CLI 的真实箱子利用率规划桥接。
- `load_best_utilization_points()`：Python 界面调用真实箱子利用率规划 CLI。
- `StackTestWindow.replan_best_utilization()`：新增独立按钮流程，不调用正式 `GeneratePlan()`。

## 边界与取舍

该功能复用 `PlanBestUtilization()` 的二维利用率搜索思想，但当前仍是有限宽度启发式搜索，不承诺数学意义上的全局最优。它与正式 `GeneratePlan()` 的职责保持分离：前者优先同层二维面积利用率，后者负责现有状态、固定成功箱和正式业务堆垛规则。
